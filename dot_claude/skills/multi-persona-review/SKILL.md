# multi-persona-review — 読み手の複眼で資料の穴を見つける

作者は自分の論理で資料を読む。読み手は自分の利害で読む。このズレを、実在の読み手を模した
ペルソナ群による blind レビューで検出する。

## パネルの構成

文書の実際のステークホルダーから 3 カテゴリで構成する（計 10〜17 名程度）:

1. **意思決定者** — この資料で判断を下す人たち。役職ごとの関心で分ける
   （CEO=事業モデル、CFO=リターンと撤退基準、CHRO=人と制度、法務=契約とリスク等）
2. **競合・敵対者** — この戦略を外から見て「怖いか、隙があるか」を判定する。
   実在の競合企業を想定し、公開情報レベルの知識を与える
3. **影響を受ける現場** — 実行を担う・変化を被る側。職種や立場で分ける。
   「この資料で自分は何を失う/得るか」「自分の扱いはどう書かれているか」を問わせる

実在の人物・企業が特定できる場合は、その実際の関心・過去の発言に合わせてペルソナを調整する。

## 実行

- 各ペルソナは**独立した subagent** で走らせ、他のペルソナの所見を見せない（blind）。
  収束を防ぎ、独立一致に意味を持たせるため
- 各ペルソナへの指示は「この資料を承認するか。しないなら何が埋まっていないからか」
  「あなたの立場で最も痛い一撃を一つ」の形で、敵対的に
- Workflow の parallel パターンが使える。ペルソナ数が多ければカテゴリごとに分割

## 統合 — 独立一致だけを昇格する

- **複数ペルソナが独立に同じ穴を指摘した場合のみ「横断 gap」に昇格**する。
  1 ペルソナだけの指摘は「ペルソナ固有の関心」として別枠に残す（捨てない）
- よく出る横断 gap のクラス: 経済性（ROI・リターン試算の欠如）/ 法務・契約の空白 /
  実行資源の不整合（計画と人員が合わない）/ 属人化 / 現場の痛み・分配への言及欠落 /
  撤退基準の不在
- カテゴリ間の一致は特に重い（例: 意思決定者と競合が同じ弱点を指す）

## 出力

1. 横断 gap（重い順、どのペルソナ群が一致したかを添える）
2. ペルソナ別所見（固有の関心）
3. 一文サマリ:「この資料は誰の、どの問いに答えていないか」

修正は作者が判断する。gap を機械的に全部埋めると資料が防御的に肥大するので、
「答える gap」と「意図的に扱わない gap（その旨を資料に一言書く）」に分ける。
