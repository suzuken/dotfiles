# Feature Map の形式

Feature Map は `features/README.md`（索引）と、機能ごとのファイルからなる。
実装の詳細は書かない。書くのは、ユーザーの経路、安定した手がかり、必要な状態、コマンド、観測できる証拠だけである。

## README.md の構成

```markdown
# <アプリ名> の検証マップ

<アプリ名> のユーザーから見える振る舞いを検証するための索引。操作の前にこの索引を読み、該当する機能ファイルを手順として使う。

## 前提状態

- 起動方法と URL（またはコマンド）、使い捨てのデータディレクトリ
- 並行実行で状態を共有しないための環境変数
- 投入する seed データ
- `control-<app> doctor` が確認すべき項目（URL、データディレクトリ、ビルドの版）
- この実行が起動していないインスタンスは操作しない

## 操作の約束

- 各手順は、断りがないかぎり前提状態から始める
- CSS セレクタや DOM の位置より、ARIA の role と名前を使う
- コマンドは書かれたとおりに実行する。引用符で囲んだ名前やフラグを変えない
- データを変更する手順の後は seed を戻す。証拠は消さない

## 証拠と skip の報告

- 操作と、その結果の状態の両方を残す
- UI の証拠は、ARIA スナップショットと、アプリが識別できるスクリーンショット
- CLI の証拠は、コマンド、stdout、stderr、終了コード
- データを変更した場合は、保存された値を読み取り専用の別経路で確かめる
- 到達できない経路は、試したコマンドと満たせなかった前提を添えて報告する
- 別の経路で確かめた機能を、skip した経路の検証として報告しない

## 機能ファイルの形式

H1 の機能名と、ユーザーから見える振る舞いを説明する 1 段落で始め、次の 4 つの H2 をこの順で置く。

1. `サブ機能`：短い ID と 1 行の説明
2. `ユーザーからの到達方法`：すべての入口
3. `操作手順（control-<app>）`：`前提:` から始め、ユーザーの操作・実行するコマンド・観測される結果を 1 項目ずつ対にする
4. `落とし穴`：検証を無駄にしたり無効にしたりする罠

## 機能一覧

- [メモの検索](./search.md)：ツールバー・キーボード・CLI からの検索、一致・空・クリアの各状態
```

## 機能ファイルの例

```markdown
# メモの検索

タイトルか本文でメモを検索し、一致したメモを開ける。一致なしと、検索が使えない状態とを区別して表示する。

## サブ機能

- `search-open`：各入口から検索ダイアログを開く
- `search-match`：タイトルと本文の一致を返し、メモのデータは変えない
- `search-empty`：一致がないときに空の状態を表示する
- `search-cli`：端末から同じ結果を返す

## ユーザーからの到達方法

- ツールバーの「検索」ボタンを押す
- 編集欄の外にフォーカスがある状態で `/` を押す
- 端末で `notes search <query>` を実行する

## 操作手順（control-notes）

前提:

- `control-notes doctor` が想定どおりの URL とデータディレクトリを返す
- seed に、本文が「予算案」のメモ「四半期計画」がある

- **ツールバーから開く。** `control-notes browser click --role button --name "検索"` を実行する。「メモを検索」という名前のダイアログが開き、検索欄にフォーカスがある
- **本文で一致させる。** `control-notes browser fill --role searchbox --name "メモを検索" --value "予算"` を実行する。結果一覧に「四半期計画」が本文の抜粋つきで出る
- **一致なし。** 値を「火山」に変える。検索の完了後、「一致するメモはありません」という status が出る
- **CLI。** `control-notes cli -- notes search "四半期" --format json` を実行する。終了コード 0 で、title が「四半期計画」のオブジェクトが 1 つ返る
- **証拠。** `control-notes browser snapshot --aria --path .verify-evidence/search/results.aria.txt` と `control-notes browser screenshot --path .verify-evidence/search/results.png` を実行する

## 落とし穴

- 編集欄や検索欄にフォーカスがあるときに `/` を押すと、検索は開かず文字が入力される
- 結果は少し遅れて更新される。決まった秒数を待たず、結果一覧か空の status が出るのを待つ
- CLI の既定の出力は人間向けである。判定には `--format json` を使う
```
