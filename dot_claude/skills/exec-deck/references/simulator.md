# シミュレータ・セクション — 選択肢を「時間軸の差」で見せる

意思決定資料で複数の選択肢（組織案・投資案・アーキテクチャ案）を比較するとき、静的な比較表の代わりに**インタラクティブなシミュレータ・セクション**を1つ置くパターン。各案に同じ時間軸を流し、「N年後の姿の差」を操作しながら見せる。推奨案が主張ではなく構造として読めるようになる。

## いつ使うか

- 選択肢が3つ以上あり、差が「時間が経つとどうなるか」に現れるとき（組織再編、投資配分、移行計画）
- decision-deck-architecture の決定項目（D1, D2…）の**直前**に置き、触ってから各決定を読ませる
- 逆に、選択肢が2つで差が一目瞭然なら表で足りる — シミュレータにしない

## 状態モデル

```
状態 = 離散オプション (3-4個) × 時間軸 (3-4段階)   → 全9〜16状態
```

- オプションには推奨を明示（ボタンラベルに ★推奨）
- 時間軸の終点は「その案を選んだ世界の到達形」。出口・撤退・成功時の形態変化まで描くと比較が締まる
- 全状態のコンテンツを**データオブジェクトとして先に書き切る**（UI から書き始めない）。状態数ぶんの一貫した記述を強制されるのがこのパターンの品質担保になる

## 3ペイン連動

1つの状態につき、次の3ペインを同時に更新する:

| ペイン | 中身 | 実装 |
|---|---|---|
| 構成図 | 組織・システムのボックス構成。状態により出現/縮小/消滅 | flex の HTML ボックス（SVGより変更に強い）。modifier class: `.virtual`(破線) `.shrink`(縮小) `.gone`(打ち消し) `.accent`(主役) |
| 資源配分 | 予算・人員の積み上げバー。**現行実データを提案の枠組みでマッピングし直す** | 幅%の flex セグメント。凡例は色固定。「現行に存在しない区分」が空になる見せ方が強い — ギャップ自体が論拠になる |
| 評価 + 起きること | 4-6軸の ◎○△× と、その状態で起きる事象の箇条書き | 表 + ul。スコアの根拠は事象側に書く（スコアだけだと恣意的に見える） |

## 実装の型

- exec-deck の 1 part（`html/parts/sim.html`）に `<style>` + `<script>` を**自己完結**で埋める。外部ライブラリなし、ビルドは通常の parts 結合のまま
- スタイルはセクション id でスコープ（`#sim .org-box {...}`）— 共通 style.css を汚さない
- JS は即時関数 + 単純な `render()`。状態は `{option, year}` の2変数だけにする
- 数値の確定度を必ず注記する: 実データ由来の起点と、将来のイメージ値を区別（source-fact-intake の規律）
- **印刷フォールバック**: `@media print` でコントロールを隠し、初期状態（推奨案 × 起点年度）を表示。印刷版はその1状態である旨を `::after` で注記

## 検証

ビルド後、Playwright の evaluate で**全状態を巡回**して壊れを機械検出する:

```js
for (const p of OPTIONS) for (const y of YEARS) {
  click(p); click(y);
  assert(合計値・見出しが期待どおり);
}
// + 各幅で overflow 監査（verification.md と同じ）
```

状態数が多いスクリーンショット目視は初期状態と極端な状態（最終年度の最悪案など）だけでよい。

## アンチパターン

- 状態ごとに内容の粒度がバラつく（データを先に書き切らないとこうなる）
- スコアだけ変えて構成図・資源が変わらない（3ペイン連動が価値の源泉）
- 資源バーを架空の数字だけで作る（現行実データの再マッピングが最も説得力を持つ）
- 印刷・PDF を考慮しない（exec-deck は投影・配布・PDF 兼用が前提）
