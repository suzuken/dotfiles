# design：設計

実装の前に、何をどう作るかを決めて残す。**この型では本番のソースを変えない。** 論点を決めるための使い捨ての試作は、`prototype` の手順で本番から隔離した場所に作ってよい。既存の振る舞いを確かめるためにアプリを動かすのはよい。実装は、ユーザーが設計を確認してから `feature` か `multi-pr` で始める。

1. 目的と完了条件を一文ずつ書く。完了条件は「誰が何をすると何が見えるか」の形にする
2. 現状を調べる。関わるコードの仕組みと、そうなっている経緯を `investigate` の手順 2〜4 で押さえる
3. 類似の設計を調べる。リポジトリ内の前例と、必要なら Web 上の事例を集め、出典を付ける
4. データの形、型、公開シグネチャを、呼び出し側の使い方から先に書く
5. 構造の違う案を 2 つ以上出す。観測で決まる論点は `prototype` で決着させる
6. 判断が要る点を、番号付きの選択肢、推奨、理由の形で示す。製品や運用の判断はユーザーに委ねる
7. 決めたことを issue か設計文書に書く。文書は `japanese-tech-writing` の「解説」として書き、構造は SVG の図で示す
8. ユーザーのレビューを待って止まる

**返答**：設計の要点、選択肢と推奨、残した文書の場所。
