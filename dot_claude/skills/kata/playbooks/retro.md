# retro：進め方の振り返り

1. `process-retro` を回す。材料は、git の履歴、PR、そしてユーザーが途中で口を挟んだ箇所
2. ユーザーが 2 回以上同じ訂正をした箇所を、ミスの分類として挙げる
3. 分類ごとに、できるだけ上の層で再発を防ぐ。順序は、構造（持ち主を 1 つにする、古いやり方を消す）、型、修正方法を示す lint、テスト、文書。新しいチェックは、過去の実際のミスで失敗することを確かめる
4. 文書でしか防げないものは、該当する skill か CLAUDE.md を直す。`kata` 自身の心得や型を直すこともある
5. 変更はユーザーの承認を取ってから適用する

**返答**：ミスの分類と証拠、選んだ層とその理由、提案する変更。
