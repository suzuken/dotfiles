# investigate：調査

読むだけの問いに、根拠つきで答える。コードもリポジトリの設定も変更しない。

1. 問いを一文で言い直す。範囲が曖昧なら、広げずにユーザーに確かめる
2. 仕組みはコードから、経緯は `git log`、PR、issue から取る。範囲が広ければ `Explore` subagent を並列に出す。Slack やドキュメントの検索は `mcp-fetcher` に任せ、要約だけを受け取る
3. 実行して確かめられることは実行する（コマンド、小さなスクリプト、ログ）
4. 主張ごとに根拠（`file:line`、PR や issue の番号、コマンドの出力）を付ける。見つからなかったことも結果として書く
5. 答えから次の作業が見えたら、型の名前（`bug-fix`、`design` など）を添えて提案する。実装には入らない

**返答**：最初の段落で問いに答える。続けて根拠、確かめていないこと、次に打てる手を書く。
