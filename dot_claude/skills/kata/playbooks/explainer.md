# explainer：解説資料

技術や仕組みを理解するための HTML 資料（テクニカルペーパー、解説、レポート）を作る。意思決定を求める資料は `deck` を使う。

1. 読み手と、読み終えた読み手が何をわかっていればよいかを一文で書く
2. 一次情報を集める。社内の資料は `source-fact-intake` の規律で扱い、確かめていない事実を断定しない
3. 構成を決める。初見の読み手のための基礎の節を置き、知っている読み手が読み飛ばせる形にする
4. 図を多く入れる。図は SVG で描く（表示先によっては Mermaid が描画されない）。SVG は CLAUDE.md の SVG 出力の規則に従う
5. 本文は `japanese-tech-writing` で書く。組織のブランドで作るなら、その組織のブランド skill を重ねる
6. ブラウザで表示を確かめる（図の崩れ、スマホの幅）
7. 共有前に、個人情報と機微な情報を落とす。公開範囲は狭く始め、公開はユーザーの確認を取ってから行う

**返答**：資料の要点、表示を確かめた範囲、公開先と公開範囲。
