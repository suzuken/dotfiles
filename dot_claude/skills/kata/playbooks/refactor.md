# refactor：振る舞いを変えない構造の変更

1. 変えない振る舞いを書き出し、それを守るテストがあるか確かめる。なければ先に書く
2. 新しい形を、型と公開シグネチャから決める
3. 呼び出し元をすべて移行し、古い API を同じ変更で消す。互換層は残さない。呼び出し元が多ければ codemod か ast-grep のルールを書き、それを成果物として残す。1 つの PR で読み切れない量なら `multi-pr` で、新しい API の追加、呼び出し元の移行（分割してよい）、古い API の削除の順に積む。古い API が残るのは、その stack が merge されるまでの間だけにする
4. 機械的な書き換えは `implementer` に、対象のパス、規約、完了条件、検証コマンドを付けて渡す。戻ってきた diff は自分で読む
5. テストと実物の確認で、振る舞いが変わっていないことを示す
6. `ship` に進む

**返答**：構造がどう変わったか、変わっていない振る舞いをどう確かめたか。
