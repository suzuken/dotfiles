# multi-pr：複数の PR にまたがる作業

1. 1〜2 ファイルで方針が明らかな変更なら、この型は使わない。`feature` か `bug-fix` に戻る
2. 未決の論点は、先に `design` か `prototype` で決める
3. 大きな作業は issue にし、必要なら sub-issue に分ける
4. PR に分ける。1 つの PR に 1 つの論点を置き、前提になる変更（型、リファクタ）を下に置く。各 PR に、変更内容、確かめ方（テスト、実物の確認、必要なら性能）、依存する PR を書く。構成は、最初の PR を作る前にユーザーへ一言で示す
5. `stacked-pr` の手順でブランチを積む
6. 1 つの PR の確かめ方がすべて埋まってから、次の PR に進む。テストが通っただけでは確かめたことにしない
7. 計画を文書にするなら作業中だけ置き、終わったら消す

**返答**：PR の構成と各 PR の状態、確かめた方法、残りの作業。
