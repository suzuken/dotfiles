# prototype：判断のための試作

試作は判断を下すための道具であり、出荷するコードではない。この型に限り、速さを品質より優先する。

1. 試作で決めることを一文で書く。決めることがなければ試作はせず、`feature` に戻る
2. 本番のソースから隔離した場所（scratchpad、別ディレクトリ）に、最も軽い手段で作る。テスト、抽象化、本番のフレームワークは要らない
3. 案を 2〜3 個作り、並べて比べられるようにする。見た目の案なら切り替えボタンや並べたスクリーンショット、ロジックの案なら同じ入力に対する出力の照合にする。ユーザーが挙げなかった案も入れてよい
4. 観測する。見た目ならスクリーンショット、振る舞いなら計時や出力を取る。観測そのものが判定になる
5. 比較、推奨、試作の場所を示す。試作は捨てるものだと明記し、選ばれた方向を `design` か `feature` に渡す

**返答**：試した案、観測した証拠、トレードオフ、推奨。
